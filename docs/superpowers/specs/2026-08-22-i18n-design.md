# i18n (6 UN Languages) for BitWatch — Design

**Date:** 2026-08-22
**Target:** index.html (single-file Vue 3 PWA), sw.js (version bump)
**Version shipped:** V6.2

## Goal

Add internationalization to BitWatch so the unlock page and watch page render all user-facing text in any of the 6 UN official languages: **Arabic (ar), Chinese (zh), English (en), French (fr), Russian (ru), Spanish (es)**. The app name "BitWatch" stays fixed across all languages; only the rest of the UI translates.

Also rename the in-app title "大饼观察Only" → "BitWatch" (the homepage title in the watch page header).

## Non-goals

- No external i18n library (project is dependency-free; no build step).
- No full RTL-perfect layout audit beyond toggling `document.dir = 'rtl'` and a couple of spacing fixes. RTL accepted as best-effort v1.
- No translation of the `manifest.json` `description` field (not visible in-app).

## Architecture

Flat dictionary i18n, no library. A `translations` object keyed by language code; each value is an object of the same message keys. A reactive `currentLang` ref drives a `t(key, ...args)` function exposed to the Vue template.

```
const SUPPORTED_LANGS = [
  { code: 'zh', label: '简体中文' },
  { code: 'en', label: 'English' },
  { code: 'fr', label: 'Français' },
  { code: 'es', label: 'Español' },
  { code: 'ru', label: 'Русский' },
  { code: 'ar', label: 'العربية' },
];

const LANG_STORAGE_KEY = 'bw-lang';

const translations = {
  en: { app_title: 'BitWatch', badge_readonly: 'Read-only', btn_export: 'Export', /* ... */ },
  zh: { app_title: 'BitWatch', badge_readonly: '加密只读', btn_export: '导出', /* ... */ },
  fr: { /* ... */ }, es: { /* ... */ }, ru: { /* ... */ }, ar: { /* ... */ },
};

function detectLang() {
  const saved = localStorage.getItem(LANG_STORAGE_KEY);
  if (saved && SUPPORTED_LANGS.some(l => l.code === saved)) return saved;
  const nav = (navigator.language || 'zh').slice(0, 2).toLowerCase();
  return SUPPORTED_LANGS.some(l => l.code === nav) ? nav : 'zh';
}

const currentLang = ref(detectLang());
const langMenuOpen = ref(false);

function t(key, ...args) {
  const dict = translations[currentLang.value] || translations.zh;
  let s = dict[key] ?? translations.zh[key] ?? key;
  // simple {0},{1} substitution for args
  args.forEach((a, i) => { s = s.replace(`{${i}}`, a); });
  return s;
}

function setLang(code) {
  currentLang.value = code;
  localStorage.setItem(LANG_STORAGE_KEY, code);
  langMenuOpen.value = false;
  document.documentElement.dir = (code === 'ar') ? 'rtl' : 'ltr';
}
```

**Fallback chain:** current language → zh → raw key. Never renders blank.

**Persistence:** `bw-lang` in localStorage. On load, `detectLang()` checks saved value first, then `navigator.language`, defaults `zh`.

**RTL:** `setLang('ar')` sets `document.documentElement.dir = 'rtl'`; other languages reset to `ltr'. Also apply on initial mount.

## Language switcher UI

Dropdown menu, placed inline **after `{{ VERSION }}`** on both pages. Shared `langMenuOpen` + `currentLang` state, so both instances stay in sync.

```
<button @click="langMenuOpen = !langMenuOpen" class="...">
  🌐 {{ langLabel(currentLang) }} ▾
</button>
<div v-if="langMenuOpen" class="absolute ...">
  <button v-for="lang in SUPPORTED_LANGS" @click="setLang(lang.code)">
    {{ lang.label }} <span v-if="lang.code === currentLang">✓</span>
  </button>
</div>
```

- Click-outside: a `v-click-outside`-style handler (or `@click` on a fixed transparent backdrop) closes the menu.
- Both pages use the same snippet; styling differs slightly (unlock page is centered/smaller).

## Testing

Manual (project has no test framework):
1. `python3 -m http.server 8080`, open `index.html`.
2. Cycle through all 6 languages; confirm every visible string on both pages translates, no key-leaks (raw keys showing).
3. Reload — chosen language persists.
4. Arabic — confirm `dir=rtl` applied, layout flips, app still usable.
5. Both pages' switchers stay in sync (switch on one, the other reflects it).
6. Existing flows intact: Face ID unlock, address add/refresh/stop, export/import, fee refresh.
7. Bump version, commit, push.

## Risks / notes

- **RTL best-effort:** Tailwind utilities aren't all RTL-aware; expect minor spacing imperfections under Arabic. Accepted for v1.
- **Translation quality:** I author fr/es/ru/ar/en translations. They'll be correct and natural but not reviewed by native speakers; the user can refine specific strings later.
- **Key leaks:** If a string is missed, `t(key)` falls back to the raw key string (visible), making gaps obvious during testing rather than silent.
